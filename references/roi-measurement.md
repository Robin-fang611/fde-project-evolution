# ROI 和基线测量

ROI 不是为了写好看的百分比，而是为了判断试点是否值得继续投入。FDE 必须先量当前基线，再谈提效。

## 基线优先

每个试点至少先回答：

- 当前每周处理多少件？
- 每件平均耗时多久？
- 需要几个人参与？
- 错误或返工大概多少？
- 延误会造成什么损失？
- 现在谁最痛？
- 哪些成本不能立刻量化，但影响管理可见性？

没有基线时，不要写“预计提升 50%”。先建议测一周。

## 常用指标

| 类别 | 指标 | 说明 |
|---|---|---|
| 时间 | 单条处理时间 | 人工流程和 FDE 辅助流程分别计时 |
| 时间 | 每周总人工时 | 单条耗时 × 周处理量 |
| 质量 | 错误率 | 错误条数 / 总条数 |
| 质量 | 返工率 | 返工条数 / 总条数 |
| 经营 | 响应时间 | 线索、报价、客服、审批等响应速度 |
| 经营 | 延误数量 | 逾期订单、逾期回款、逾期采购 |
| 管理 | 异常发现数 | 系统或流程暴露出的异常数量 |
| 采用 | 人工复核时间 | AI 输出后仍需人工检查的时间 |
| 风险 | 敏感数据触点 | 涉及客户、财务、合同、员工等数据点 |

## 简化 ROI 公式

```text
每周节省人工时 = (人工单条耗时 - FDE辅助单条耗时 - 复核耗时) × 周处理量

每月人工节省金额 = 每周节省人工时 × 4.33 × 估算小时人工成本

错误减少收益 = 减少错误数 × 单次错误平均损失

总收益 = 人工节省金额 + 错误减少收益 + 可量化延误减少收益
```

不可量化收益也要记录，但不能混入硬 ROI：

- 管理层更早看到异常。
- 新员工更容易接手。
- 关键经验不再只存在个人脑中。
- 部门之间扯皮减少。

## 结论写法

- 可以继续：节省明确、风险可控、使用者愿意继续用。
- 缩小范围：价值存在，但字段、规则或责任人不清。
- 先补数据：流程痛点真实，但数据质量不支持自动化。
- 暂停：节省不明显、复核成本过高或组织阻力太大。
