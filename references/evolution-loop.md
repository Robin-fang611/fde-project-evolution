# FDE 进化循环

这份文档把 agent 进化思想翻译成 FDE 项目的实际工作循环。在本 skill 的默认场景里，进化不是让模型神秘变强，而是让 FDE 在一个项目里持续积累业务理解、可复用流程和安全边界。

## 可借鉴的 agent 思路

- Hermes Agent：强调长期记忆、重复任务学习和技能沉淀。落地翻译：把项目经验写成可检查的记忆和 playbook，不依赖聊天历史。
- Reflexion：通过语言反思让 agent 从反馈中改进。落地翻译：把失败、复盘、客户反馈写成“下次必须注意”的规则。
- Voyager：用任务课程、技能库和环境反馈持续积累能力。落地翻译：把高频业务流程做成场景卡片和可复用 SOP。
- Generative Agents：把观察、反思、计划分开。落地翻译：先收集事实，再总结经验，最后决定下一步。
- SE-Agent 类思路：复盘过去轨迹，修订、重组、优化。落地翻译：比较多个项目尝试，保留有效打法，淘汰脆弱捷径。

## 六步循环

每次手动或自动化进化，都按这个顺序走：

1. 观察
   - 阅读最近日志、业务记录、会议纪要、访谈、表格样本、测试结果、客户反馈、历史 Codex 输出。
   - 区分事实、观点、指令、假设和问题。
   - 中小企业项目还要看：Excel 导出、ERP/CRM 导出、聊天摘要、截图、审批记录、SOP、销售/财务/采购/库存/生产/客服记录。

2. 诊断
   - 找重复卡点、人工返工、错误来源、责任不清、数据缺口、采用阻力和风险捷径。
   - 先判断根因是数据质量、责任人、习惯、权限、成本、工具不匹配，还是业务规则没说清。

3. 提炼
   - 把证据转成短规则。
   - 只有未来同类项目还会用到的，才算值得保存。
   - 保留企业自己的业务叫法，不要把所有土话都改成咨询黑话。

4. 修补
   - 更新项目记忆、playbook、检查清单、场景卡片或 skill 建议。
   - 每个更新都要能追溯到证据。

5. 计划
   - 给出少量下一步动作。
   - 至少包含一个让 FDE 下一次更快或更稳的改进。

6. 验证
   - 检查新规则是否和 `AGENTS.md`、安全规则、现有命令、项目事实冲突。
   - 不确定的内容标成假设，不要写成规则。

## 什么经验值得保存

值得保存：

- 能避免重复错误。
- 能加快高频流程。
- 能记录业务流程、部门规则、数据来源、审批路径、经营偏好。
- 能记录产品、架构、安全、部署或成本约束。
- 能防止未来 agent 重复争论已经决定的事情。
- 能把分散记录变成可执行清单。

不要保存：

- 一次性闲聊。
- 没证据的猜测。
- 密钥、客户隐私、敏感财务或员工信息。
- Codex 本来就知道的泛泛工程常识。
- 和项目负责人或 `AGENTS.md` 冲突的指令。

## 项目记忆模板

`project-profile.md`：

```markdown
# 项目画像

## 企业类型

## 业务目标

## 经营指标

## 部门和责任人

## 当前工具

## 当前数据来源

## 关键流程

## 验证方式

## 稳定约束

## 未决问题
```

`operating-rules.md`：

```markdown
# 项目操作规则

## 安全和权限

## 数据处理

## 业务沟通

## 交付质量

## 发布/部署

## 本项目禁区
```

`evolution-log.md`：

```markdown
# FDE 进化日志

## YYYY-MM-DD

### 阅读证据

### 新增经验

### 更新的 Playbook

### 风险和后续动作
```

`playbooks/<workflow>.md`：

```markdown
# <流程名称>

## 适用场景

## 需要输入

## 操作步骤

## 人工复核点

## 验证方式

## 常见失败
```
