# FDE Skill 优化路线图

基于 8 个知名案例的对照分析，诊断当前 FDE skill 的不足，给出具体优化方案。

---

## 一、当前状态诊断

### 已有的（不错的部分）

- 方法论方向正确：先业务后技术、先小闭环后大系统、人机协同默认模式
- 场景评分表是核心资产，8 维度 × 5 分制有操作性
- 安全边界清晰，知道什么不该做
- 中国民企洞察真实，"土办法"视角不虚伪

### 缺失的（案例对照暴露的短板）

对比 8 个案例，当前 skill 缺 5 样东西：

| 缺失项 | 案例中的表现 | 当前 skill 状态 |
|---|---|---|
| 真实数据样例 | 川航有扫码报工流程、中山有 Excel 客户表 | 全是空白模板，零样例数据 |
| 工具选型指导 | 案例从 Excel 到 ERP 有清晰梯度 | 只提了工具名（Excel/企微/ERP），没说怎么选 |
| 角色化输出 | 百果园有"店长秘书"、瑞幸有"福利官" | 只有一个输出格式模板，没有角色化视角 |
| 可运行 Demo | 钱大妈订货系统可演示、优克拉 50+ Skill 可复用 | 只有一个扫描脚本，没有业务逻辑 Demo |
| ROI 计算框架 | 每个案例都有基线和改善数据 | 只提了"要量基线"，没给怎么量的方法 |

### 根本问题

**当前 skill 是给 AI 看的，不是给人用的。** 8 个案例之所以有说服力，是因为每个都有"前 vs 后"的数据、有具体工具名、有操作步骤。FDE skill 的方法论是对的，但一个新人拿着它去客户现场，发现所有东西都要从零开始填。

## 二、优化方案：四层推进

### 第一层：让模板"活起来"（预计 2 周）

**目标**：每个空白模板配 1-2 个填写好的样例，新人能对照填空。

**具体动作**：

| 动作 | 产出物 | 优先级 |
|---|---|---|
| 基于中山五金案例，制作"客户分级 Excel 样例" | `examples/customer-grading/` | P0 |
| 基于川航机械案例，制作"工序报工流程样例" | `examples/production-tracking/` | P0 |
| 基于一个模拟贸易公司，制作"Excel 对账异常检测样例" | `examples/reconciliation-check/` | P1 |
| 场景评分表补充一个填写好的样例（每个维度都有评分理由） | 更新 `practicality-validation.md` | P0 |
| A/B 测试报告模板补充一个填写好的样例 | `examples/ab-test-report-sample.md` | P1 |

**样例内容标准**：
- 有真实感的模拟数据（公司名、人名、金额全部虚构但逼真）
- 有"原始数据"和"处理后结果"的对照
- 有每一步的操作说明，新人可以手动重复

### 第二层：补充工具选型框架（预计 1 周）

**目标**：FDE 能根据企业实际情况，给出有依据的工具建议。

**具体动作**：

| 动作 | 产出物 | 优先级 |
|---|---|---|
| 写一个"工具选型决策树"：从人数、预算、IT能力、数据量 4 个维度出发 | `references/tool-selection-guide.md` | P0 |
| 整理常用工具的"FDE 适用评估"（简道云/轻流/企微/飞书/钉钉/金蝶/用友） | 同上 | P1 |
| 每种工具标注：适合什么场景、不适合什么场景、大概费用、学习门槛 | 同上 | P1 |

**工具选型决策树的核心逻辑**：

```
企业有 IT 团队吗？
├── 有 → 团队 ≥ 3 人？ → 可以考虑自研 + 开源组件
└── 没有 → 员工都用微信吗？
    ├── 是 → 企业微信生态优先（智能表格 + 审批 + 客户联系）
    └── 用钉钉 → 钉钉生态优先（宜搭 + 悟空 AI）
        用飞书 → 飞书生态优先（多维表格 + 审批）

日处理数据量 > 1000 条吗？
├── 是 → 需要数据库或 SaaS 系统
└── 否 → Excel/WPS + 企微/钉钉/飞书足够

预算 < 5 万/年 吗？
├── 是 → 企微/钉钉/飞书免费功能 + Excel
└── 否 → 无代码平台或轻量 SaaS
```

### 第三层：角色化输出模板（预计 1 周）

**目标**：FDE 对不同角色说不同的话，输出不同格式的内容。

**当前问题**：skill 只有一个统一输出格式，但实际项目中：

- 老板想要 1 页纸结论
- 部门负责人想要流程 + 指标 + 风险
- 一线员工想要操作步骤 + 遇到问题怎么办
- 开源读者想要完整案例 + 数据 + 代码

**具体动作**：

| 角色 | 输出模板 | 内容特征 |
|---|---|---|
| 老板 | `report-boss.md` | 1 页，只讲钱/时间/风险，不放技术细节 |
| 部门负责人 | `report-manager.md` | 流程对比、指标、试点计划、ROI 估算 |
| 一线员工 | `guide-operator.md` | 操作步骤、截图、常见问题、找谁帮忙 |
| 开源读者 | `case-opensource.md` | 完整故事、数据对比、可复现代码、脱敏说明 |

**对应到具体案例**：

- 瑞幸给店长的订货建议只显示 3 个数字（建议订货量、理由、历史同期），不给公式
- 百果园给加盟商的看板只显示关键预警（现金流、陈列、食安），不展示数据模型
- FDE 也应该做到：对谁说、说什么、用什么格式，提前想好

### 第四层：可运行 Demo（预计 3-4 周）

**目标**：新用户 clone 项目后，5 分钟内能跑出第一个结果。

**这是从"文档项目"变成"工具项目"的关键一步。**

**Demo 设计**：

| Demo | 输入 | 处理 | 输出 | 技术 |
|---|---|---|---|---|
| 客户分级 | Excel 客户表 | Python 脚本读表、打分、分级 | 分级结果 + 跟进建议 | Python (零依赖) |
| 对账异常检测 | 订单表 + 收款表 | 比对金额、日期、客户名，标异常 | 异常清单 Excel | Python (零依赖) |
| 老板日报生成 | 销售表 + 回款表 + 库存表 | 汇总昨日数据，标异常 | Markdown 日报 | Python (零依赖) |
| 场景评分 | 填好的场景池 CSV | 读取、打分、排序 | 推荐 Top 3 场景 | Python (零依赖) |

**技术要求**：
- 零第三方依赖（只用 Python 标准库）
- 每个 Demo 一个独立文件夹，含 `README.md`、`sample_data/`、`run.py`、`output/`
- 样例数据全部虚构，标注"模拟数据"
- README 写清楚：这是什么场景、怎么跑、输出怎么看

**目录结构规划**：

## 三、优先级排序

按"对开源传播的杠杆率"排序，而不是按"对方法论完备性"排序。

| 优先级 | 动作 | 理由 |
|---|---|---|
| P0 | 补充 2-3 个填写好的样例（场景评分表 + A/B 报告 + 客户分级） | 这是"30 分钟第一次收获"的前提 |
| P0 | 写一个"工具选型决策树"文档 | 新 FDE 最常问的就是"用什么工具" |
| P0 | 做"对账异常检测"可运行 Demo | 最通用的场景，几乎每个小贸易公司都要做 |
| P1 | 做"客户分级"可运行 Demo | 第二通用的场景 |
| P1 | 角色化输出模板（老板版 + 一线版） | 提升专业度 |
| P1 | 做"老板日报"可运行 Demo | 见效最快，老板最喜欢的场景 |
| P2 | 补充更多样例数据、边缘案例 | 丰富度提升 |
| P2 | CONTRIBUTING.md + Issue 模板 | 开源社区准备 |
| P3 | CI + 测试 | 代码质量 |
| P3 | 英文版 README | 国际化 |

---

## 四、不做的事

- ❌ 不追求案例数量。3 个做好了的 Demo > 30 个做了一半的 Demo
- ❌ 不引入重量级框架。每个 Demo 零依赖运行
- ❌ 不动现有 skill 的核心方法论。优化是补充，不是推翻
- ❌ 不等"完美"再发布。做完 P0 就可以公开早期版本
- ❌ 不做大而全的平台。保持"工具包"定位，不做 SaaS

---

## 五、1000 Star 的可行性重估

对比 8 个案例的开源影响力，FDE 项目要达到 1000 star 需要满足：

| 条件 | 当前状态 | 差距 |
|---|---|---|
| 30 分钟内获得第一次收获 | ❌ 不满足 | 需要 P0 Demo |
| 有 3+ 可复现的真实感场景 | ❌ 零 | 需要 3 个可运行 Demo |
| 方法论有鲜明观点 | ✅ 已有 | 保持 |
| 中文 SME AI 落地领域无竞品 | ✅ 确实是空白 | 抢时间窗口 |
| 有传播钩子（"混乱 Excel 变 AI 小闭环"） | ⚠️ 有概念缺例子 | 需要好的 README + 截图 |
| 社区能贡献 | ❌ 没有入口 | 需要 CONTRIBUTING + 模板 |

**修正后的 star 预估**：

| 阶段 | 预估 | 关键动作 |
|---|---|---|
| 当前（纯文档） | 10-30 | — |
| 完成 P0（样例 + 1 个 Demo + 工具选型） | 80-150 | Pre-alpha 发布 |
| 完成 P1（3 个 Demo + 角色化模板） | 200-400 | Alpha 发布，发中文社区 |
| 完整发布（5+ Demo + 社区入口 + 真实案例） | 400-700 | 正式发布，持续运营 |
| 1000 Star | 需要社区贡献 + 媒体传播 + 持续迭代 | 品类天花板附近，有可能但不确定 |
