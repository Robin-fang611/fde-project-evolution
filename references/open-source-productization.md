# 开源产品化

这份文档用于把 FDE 项目经验包装成公开 GitHub 项目。目标是帮助想做实战 FDE 的人，尤其是服务中国本土中小企业 AI 化、数字化的人。

项目质量标准按至少 500 star、争取 1000 star 设计。这个项目的主产品仍然是 FDE skill，但不能只有抽象说明；它需要样例、模板和案例来证明 skill 能指导真实工作。

## star 目标的现实要求

500-1000 star 通常需要：

- 一句话说清楚项目解决什么问题。
- 目标用户非常明确。
- 30 分钟内能获得第一次收获。
- 有可运行或可检查的样例。
- 有可直接复用的模板。
- 有可信的案例或测试报告。
- 有贡献入口，让别人能提交场景、案例、模板或脚本。
- 有鲜明观点，不是泛泛 AI 咨询话术。

不要追求宽泛。要让目标用户觉得：“这说的就是我每天遇到的复杂琐碎工作。”

## 推荐定位

推荐定位：

> 一个面向中国中小企业真实业务流程的 FDE skill 和方法工具包，帮助 Codex/Claude Code 把混乱的 Excel、微信、ERP 导出和人工流程，转成可验证、可试点、可复用的 AI/数字化小闭环。

主要用户：

- 想成为 FDE 的人。
- 给本地企业做 AI 落地的顾问或创业者。
- 中小企业内部的运营、信息化、数字化负责人。
- 想做 AI 转型服务的创业者。
- 想让 agent 围绕项目持续积累经验的人。

不是主要用户：

- 大企业架构团队。
- 只收藏 prompt 的用户。
- 只想看自动 agent 展示 demo 的用户。
- 一上来就要替换 ERP/CRM 的团队。

## 应该优先公开的资产

优先做这些别人能马上用的东西：

- 场景评分表。
- 流程调研访谈提纲。
- A/B 测试模板。
- 匿名案例。
- 模拟 Excel/CSV/PDF/聊天记录样本。
- 提取、对账、异常报告、日报生成脚本。
- 经营简报模板。
- 部门 playbook。
- 数据权限和风险清单。
- FDE 项目记忆模板。
- Codex skill 示例。
- 支撑 skill 判断的最小可运行样例。

避免：

- 空泛“AI 转型框架图”。
- 没有样本的大架构方案。
- 夸大 ROI 的案例。
- 依赖私有服务、别人跑不起来的 demo。
- 看起来像咨询 PPT、短期不能直接使用的模板。

## 30 分钟第一次收获

一个新用户应该能在 30 分钟内完成：

1. 下载或 clone 项目。
2. 选一个 SME 业务场景。
3. 用实用性评分表打分。
4. 查看或运行一个支撑样例，理解 skill 的输出标准。
5. 生成一份自己的试点简报或 skill 输入材料。

做不到这一点，就还不适合公开大规模传播。

## 仓库质量标准

公开发布前建议包含：

- `README.md`：问题、受众、快速开始、样例、截图或输出效果。
- `LICENSE`：明确开源协议。
- `CONTRIBUTING.md`：说明如何贡献代码、场景、案例、模板。
- `CODE_OF_CONDUCT.md`：如果期待社区参与，需要有基本社区规则。
- `docs/`：方法论、场景库、案例格式。
- `examples/`：支撑 skill 的可运行或可检查 SME 工作流样例。
- `templates/`：评分表、访谈提纲、试点 brief、A/B 报告。
- `skills/` 或 `codex-skills/`：Codex skill 分发目录。
- `tests/`：对提取、对账、报告等脚本做基础验证。

官方参考：

- GitHub README 指南: https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes
- GitHub Community Profile: https://docs.github.com/articles/viewing-your-community-profile
- Open Source Guides: https://opensource.guide/starting-a-project/

## 公开案例格式

每个公开案例要回答：

- 企业或部门类型是什么？
- 原来的流程怎么跑？
- 痛点在哪里？
- 有哪些数据、文件、消息或系统记录？
- FDE 试点做了什么？
- A/B 或前后对比怎么测？
- 哪些指标改善了？
- 哪些地方没做成？
- 下一个 FDE 应该复制什么、避开什么？

公司名称、客户信息、价格、合同、员工、财务数据必须脱敏。

## 增长抓手

高传播价值内容：

- “做 AI agent 前，先自动化这 10 个中小企业流程”
- “FDE 场景实用性评分表”
- “混乱 Excel/微信/ERP 导出的样例实验室”
- “真实运营场景的 A/B 提效报告”
- “让 Codex 围绕项目持续进化的 skill”
- “中小企业 AI 数字化一周试点模板”

传播渠道：

- GitHub README 和置顶样例。
- 创业者、AI builder、企业服务、运营社群。
- 中文社交平台上的实战拆解。
- 短文章：展示一个乱流程如何变成可跑试点。

## 发布阶段

Pre-alpha：

- skill 和方法论完整。
- 有 5-10 张场景卡片。
- 有一个模拟样例。
- 至少有一个已填写的场景评分表和一个 A/B 报告样例。

Alpha：

- 有 3 个可运行或可检查样例。
- 评分表和模板打磨好。
- 有一个端到端测试报告。
- 有工具选型指南、角色化输出模板和 ROI 测量模板。

公开发布：

- 有 5 个以上场景样例。
- README 和贡献指南清晰。
- 至少一个真实或强仿真的案例。
- 有 issue 模板，方便别人提交场景和案例。
- 没有私密数据和无法验证的宣传。

500 star 标准：

- 项目名和一句话定位好记。
- 样例不像玩具，而像真实工作。
- 贡献者知道怎么补充场景。
- 用户能很快获得第一次收获。
- 方法论足够有态度，不是泛泛而谈。

1000 star 标准：

- 社区能持续贡献匿名案例。
- 场景库会越积越多。
- benchmark 模板让不同案例可以横向比较。
- 项目成为实战 FDE 的参考资料，而不只是单一项目工具。
